2. USER PROFILE:
The User Profile contains key information about individuals who have used the computer. It
includes the name of the user, the type of account they used, where their personal data is
stored, when they last accessed the device, and the last time their password was changed. This
data helps investigators understand who was using the device, what kind of access they had,
and when they were active.
• Username
This is the name of the person or account holder who has used the device. It helps identify
different users on the same system.
• Type of User
This shows whether the user is a local user (created only on this device), a
domain user (linked to a larger network like in offices or institutions), or a
system account (used internally by Windows or certain software). Understanding
the type helps clarify the level of access and the role of the user.
• Profile Path:
This is the specific location on the computer’s storage where the user’s files and data are
saved. For example, a typical path like C:\Users\Sandeep shows where that user’s documents,
browser data, and application files are stored.
• Last Local Login:
This shows the exact date and time the user last signed into the device. It helps in determining
recent usage activity and whether the account was active during the time of interest.
• Password Change:
This shows when the password for the account was last changed. This can indicate whether
the user was actively maintaining the account or if there might have been any recent changes
suggesting suspicious activity.
Status:
All user profile information was examined to determine the users present on the system, the
nature of their accounts, and their most recent activity.

C. OBJECTIVE, PROCEDURE & OBSERVATION:
-Desktop [Ex-5]
1. User Accounts & Login Activity
Objective:
To find out who used the system, when they logged in, and whether any unauthorized person
tried to access it.
Procedure:
• Checked all user accounts created on the computer.
• Reviewed system logs to track login and logout events.
• Looked for any login attempts during unusual hours or from unknown users.
Observation:
All user accounts on the Desktop looked normal. There were no strange logins or attempts by
outsiders to get into the system. Everyone who used the Desktop seemed to be an authorized
user.
2. File Access and Handling
Objective:
To check if important files were opened, changed, copied, or deleted in ways that go against
hospital policies.
Procedure:
• Examined file access logs and timestamps for unusual activity.
• Looked for files that were renamed, compressed, or deleted.
• Checked for signs of mass file movement or use of backup folders.
Observation:
The files on the Desktop were used in a regular way. No files were deleted, renamed, or copied
in a suspicious manner. Everything matched normal work activity.

3. USB and External Device Usage
Objective:
To find whether any external storage devices were connected and possibly used for data
movement or copying.
Procedure:
• Analyzed USB device history using system logs and registry data.
• Identified all connected USB devices, along with timestamps.
• Matched this with any file access or data transfer events.
Observation:
The system records showed that USB storage devices, such as pen drives or external drives,
were connected to the Desktop. These entries confirm that the devices were attached at some
point. However, the records do not confirm whether the connected devices were actively used
for opening, copying, or transferring files.
4. Network Connections
Objective:
To see whether the system connected to any suspicious or unauthorized websites or services.
Procedure:
• Checked network logs for connections to IP addresses or external servers.
• Looked for the use of remote desktop or other remote access tools.
• Flagged unusual or persistent connections that could suggest data exfiltration.
Observation:
The Desktop was used for remote connections and also linked with a mobile phone through the
“Your Phone” app. This means data could have been accessed or transferred remotely.

5. Installed Applications & Tools
Objective:
To check for the presence of unauthorized programs or tools that could allow remote access or
conceal activities.
Procedure:
• Reviewed the list of installed programs.
• Searched for known remote control, data wiping, or suspicious tools.
• Looked at usage logs for recently launched applications.
Observation:
Only normal programs were installed. No special tools for hacking, remote control, or hiding
activity were found.
6. Registry Analysis
Objective:
To identify startup entries, recently used devices, or any traces left by unauthorized tools.
Procedure:
• Searched for entries in startup/run locations.
• Checked USB registry keys and recently opened file lists.
• Analyzed persistence mechanisms that might be used by attackers.
Observation:
The system’s settings and records looked normal. There were no signs that someone tried to
secretly make changes or hide their activity.
7. Scheduled Tasks & Startup Items
Objective:
To check for scheduled actions or programs that may launch automatically without user
awareness.
Procedure:
• Listed all scheduled tasks and verified their triggers.
• Analyzed the task contents and execution logs.
• Looked for links to scripts or unknown applications.
Observation:
The Desktop did not have any hidden programs set to run automatically. All scheduled
activities were regular and safe.
